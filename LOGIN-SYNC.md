# Shared Nova login

This feature is built but stays inactive on a copy until its exact HTTPS domain is approved. It does not automatically trust copies of Nova.

1. Deploy these changes to the original Nova and the new copy. Both must use the existing Nova Firebase project.
2. Publish `firebase-voice.rules.json` to Firebase Realtime Database. The new `novaAuthHandoffs` records must stay completely private to the server.
3. On both deployments, set `NOVA_LOGIN_ORIGIN` to `https://novaoffical.vercel.app` and `NOVA_LOGIN_TRUSTED_ORIGINS` to the exact new site origin, such as `https://your-new-nova.vercel.app`. Multiple approved origins can be comma-separated. No paths, trailing slashes, HTTP, or wildcards.
4. The original deployment needs its existing `FIREBASE_SERVICE_ACCOUNT_JSON` server credential. Never place that credential in public files or browser code.
5. Add the new domain to Firebase Authentication → Settings → Authorized domains. Redeploy after changing environment variables.
6. In one browser, sign into the original Nova, then open the new site's home page. It will briefly visit the original site and return with the same account. The ordinary account restore loads existing profile settings and saves.

The handoff uses a random code that expires in 90 seconds and can be redeemed only once, from its approved destination, using a secret generated by the requesting browser tab. No passwords, Firebase ID tokens, or custom login tokens go in URLs. Short-lived codes and request state travel in URL fragments and are removed immediately on arrival. Custom tokens are returned only in a no-store HTTPS response to the approved site.

If the original site is unreachable, the user is logged out there, the rules or server credentials are unavailable, or the request expires, normal login remains available. It will not loop through automatic redirects in the same tab. Log out and Add another account explicitly skip automatic login. Existing destination logins are never replaced. This feature works in the same browser profile with the original site's saved login; it cannot transfer a login from another device or recover forgotten credentials.

For local development the handoff stays disabled: production login destinations must use HTTPS. API tests simulate the complete issue and redemption flow without connecting to live accounts. No production domains or Firebase rules are deployed by adding these files.
